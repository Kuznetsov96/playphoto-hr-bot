# Флаг записи выручки в ДДС вебаппа

Ветка `feat/dds-api-flag` от `dev`. Добавлен булев вход деплоя
`dds_api_write_enabled`; включённый даёт контейнеру `FINANCE_DDS_TARGET=both`,
выключенный — `sheets`.

## Зачем

В приложении 7 локаций из 17, остальные десять ведёт бот. Их выручка перестала
попадать в ДДС вебаппа 21 августа, дыра растёт примерно на 25 тыс. грн в день.
Код передачи был готов (`src/services/finance/dds-writer.ts`,
`src/services/aws-business-client.ts:484`), но на проде `FINANCE_DDS_TARGET` не
задана и действует умолчание `sheets`. Не хватало только способа задать её так,
чтобы значение пережило следующий релиз.

## Выбор преобразования: вариант (б)

Флаг булев (этого требует контракт), конфиг бота ждёт строку из трёх значений.
Выбран вариант (б) — отдельная переменная `AWS_DDS_API_WRITE_ENABLED` плюс
правка `src/config.ts`. Вариант (а) — тернарник в bash — отклонён, и решает тут
не вкусовое «честнее», а сам контракт.

`scripts/aws/check-production-deploy-contract.mjs` выводит список
проверяемых флагов из воркфлоу регуляркой:

```js
const flags = [...content.workflow.matchAll(/printf '(AWS_[A-Z0-9_]+_ENABLED)=%q\\n'/gu)]
```

и только для попавших в этот список требует все четыре звена. Строка вида
`printf 'FINANCE_DDS_TARGET=%q\n' "$(... && echo both || echo sheets)"` под
шаблон `AWS_*_ENABLED` не подходит. То есть вариант (а) прошёл бы мимо
проверки целиком: контракт молча счёл бы, что нового флага нет, и потеря любого
звена дала бы ровно тот отказ, ради которого проверка написана — зелёный
деплой, `true` в сводке и выключенная передача в боте. Так уже случилось с
`AWS_REPLACEMENT_AUTO_CONFIRM_ENABLED`.

Вариант (б) даёт флагу имя нужной формы, поэтому он подхватывается проверкой
автоматически, без правки самого чек-скрипта. Преобразование булева в строку
живёт в `src/config.ts`: там оно типизировано, покрыто тестами и видно из кода,
который его читает, а не спрятано в bash-подстановке внутри YAML.

Режим `both`, а не `api`, — сознательно: Google-таблица остаётся рабочей, и
расхождение между двумя путями обнаружится на реальных данных.

где булева флага деплоя нет.

## Умолчание

`default: true`, как у всех соседей и как требует контракт: форма переписывает
окружение целиком, поэтому `default: false` превратил бы любой обычный деплой в
тихий откат этой передачи.

Флаг ещё не раскатан, и правило контракта на этот случай прямое: «A
not-yet-rolled-out flag is therefore held back by UNTICKING it on its first
deploy, not by defaulting it to `false`». **Первый выкат делается со снятой
галочкой.** Осторожность выражается действием при запуске формы, а не
умолчанием в файле.

## Что увидит владелец в форме

В конце списка переключателей, после «Revoke Telegram access…», появится
одиннадцатый, включённый по умолчанию:

> **Record bot-led location revenue in the webapp cash-flow ledger alongside the Google sheet** — ☑

Порядок действий:

1. **Первый запуск — галочку СНЯТЬ.** Это выкатывает код флага, не меняя
   поведения: бот продолжает писать только в таблицу.
2. **Второй запуск — галочку оставить.** Бот начинает писать в оба места
   (`both`), таблица остаётся рабочей.
3. Откат — снять галочку и запустить форму снова; деплой кода для этого не
   нужен.

В сводке деплоя добавлена строка `- DDS API revenue write: \`true|false\``.
Заодно в сводку добавлены две строки, которых там не было при живых флагах, —
`Parcels canonical read` и `Access revocations`: сводка должна показывать всё,
что деплой выставил.

## Проверки

Все прогоны — в окружении переменных из job `quality` того же воркфлоу
(без них `src/config.ts` завершает процесс, и тесты падают одинаково до и после
правок — сверено прогоном на `git stash`).

| Проверка | Результат |
| --- | --- |
| `npm run check-production-deploy` | contract is valid + симуляции деплоя и отката пройдены |
| `npm test` | 119 файлов, 768 тестов, все зелёные |
| `npm run build` (`tsc`) | без ошибок |
| `npm run check-cycles` | без циклов |
| `npm run check-menu-ids` | без дублей |
| `npx eslint src/config.ts src/services/finance/dds-writer.ts` | чисто |
| `npx eslint .` | 247 проблем и до, и после правок — новых не добавлено |

Отдельно проверено, что контракт действительно **видит** новый флаг, а не
пропускает его: список, выведенный той же регуляркой, содержит 11 флагов вместе
с `AWS_DDS_API_WRITE_ENABLED`; временное удаление `export` в start-хуке и
временное удаление `set_env` каждое роняет проверку; замена умолчания на `false`
даёт ошибку «workflow input dds_api_write_enabled defaults to false». После
восстановления — снова зелено.

Добавлены четыре теста в `src/__tests__/config-flags.test.ts`: флаг не задан →
`sheets`, `false` → `sheets`, `true` → `both`, явный `FINANCE_DDS_TARGET`
перекрывает вывод.
