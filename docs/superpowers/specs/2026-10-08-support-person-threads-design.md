# Підтримка: одна постійна тема на людину

**Date:** 2026-10-08
**Status:** Approved by owner (design in chat 08.10); implementation in `feat/support-threads`.

## Problem

Аудит 08.10.2026 на живих даних (30 днів):

| Що | Число |
|---|---|
| Нових тем у чаті підтримки | 196 (109 тікетів, 71 вихідна 📤, 16 по задачах 📎) |
| Тем на одну людину | медіана 3, до 9 |
| Повідомлень фотографинь, що отримали «Не розпізнав цю команду» замість підтримки | 44 від 22 людей |
| Закриття тікетів | 87 з 91 — автоматом через 48 год, вручну 2 |
| Хто відповідає | Vitalii 1100, акаунт PlayPhoto Support 542, Alyona 40 |
| Тем по задачах, відкритих понад 7 днів | 61 |

Причини:

1. **Код локації в назві зламаний.** `LOCATION_SHORTCUTS` має ключі з кириличним містом («Smile Park|Львів»), а в базі міста латиницею. Збіг завжди падає в пошук за назвою: всі Smile Park → `PidDubom`, всі Fly Kids → `Patona`, всі Karamel → `Kolom`. Локація — «найближча зміна», а не сьогоднішня.
2. **Розмова з однією людиною розкидана по 3–4 темах**, і відповідь фотографині на задачу йде в тікет, а менеджер чекає в темі задачі.
3. **Повідомлення без відкритого тікета губиться** — stray handler відповідає «Не розпізнав».
4. **Немає цитат, правок, реакцій.** Пересилання не пам'ятає пари «повідомлення в темі ↔ у приватному чаті», `allowed_updates` без `edited_message` і `message_reaction`.
5. **Шум:** перейменування на кожен статус, «Administrator closed this topic», закриті теми назавжди в списку, сім форматів назв, змішані мови в адмінському UI.

## Goal

Менеджерка на бігу з телефона за секунду бачить, **хто** пише, **звідки** і **чи чекає відповіді**; відповідає в одному місці; фотографиня не губиться і отримує відповідь із цитатою.

## Рішення власника

- Одна постійна тема на людину (StaffProfile). Кандидаток на онбордингу немає.
- Тема **ніколи не закривається**. Статус рахується сам; «чекає/відповіли» видно з прев'ю останнього повідомлення («You: …» чи «PlayPhoto INFO: …»), іконка — лише для рідкісних станів (рішення власника 08.10: кожна зміна іконки пише в тему службовий рядок).
- Назва: `Прізвище · Місто · Майданчик Філія`, латиницею для точки. Прізвище без ініціалів; ініціал додається лише при збігу прізвищ.
- Внутрішніх нотаток немає: усе, що людина пише в темі, йде фотографині.
- Покликати Кузнєцова або Гупалову — кнопкою; вони можуть повернути тему Support-акаунту.
- Службові тексти для команди — англійською; для фотографинь — українською на «ти».
- Старі теми лишаються архівом. LOGISTICS не чіпаємо.

## Design

### Дані

```prisma
enum SupportThreadStatus { WAITING ANSWERED ESCALATED ARCHIVED }

model SupportThread {
  id                    String              @id @default(cuid())
  userId                String              @unique
  chatId                BigInt
  topicId               Int
  title                 String
  status                SupportThreadStatus @default(ANSWERED)
  escalatedToTelegramId BigInt?
  cardMessageId         Int?
  cardDay               String?   // київська дата останнього оновлення картки
  noticeDay             String?   // київська дата рядка «сьогодні на іншій точці»
  lastStaffAt           DateTime? // будь-яке повідомлення фотографині
  lastQuestionAt        DateTime? // повідомлення, що потребує відповіді
  lastSupportAt         DateTime?
  createdAt / updatedAt
  @@unique([chatId, topicId])
}

model SupportMessageLink {
  id               Int     @id @default(autoincrement())
  threadId         String
  direction        String  // IN фотографиня→тема, OUT тема→фотографиня, CONTEXT пост бота з контекстом
  topicChatId      BigInt
  topicMessageId   Int
  privateChatId    BigInt?
  privateMessageId Int?
  contextText      String? // CONTEXT: що показати фотографині, коли відповідають на цей пост
  createdAt        DateTime @default(now())
  @@unique([topicChatId, topicMessageId])
  @@index([privateChatId, privateMessageId])
}
```

Зв'язки живуть 90 днів (щоденне прибирання). Старі `SupportTicket`, `OutgoingTopic`, поля теми в `TaskProofSubmission` лишаються архівом і для впізнавання старих тем.

Усе вмикається прапорцем `SUPPORT_THREADS_ENABLED` (типово `false`). Без нього нові звернення йдуть старими тікетами, але відповіді в уже створених постійних темах і кнопки їхніх карток працюють — інакше після відкату вони б мовчки губились (старі тікети перехід уже закрив).

### Назва і статус

- **Назва** `Бланк · Lviv · Dragon Park 2`. Основна точка — найчастіша за змінами −60…+30 днів, інакше точка профілю, інакше лише прізвище. Місто — `location.city` (латиниця; кирилицю нормалізує `normalizeCity`), майданчик — `name` + `branch`. Перейменування лише коли текст змінився (щоденна задача).
- **Іконка** з набору `getForumTopicIconStickers`: 👀 ESCALATED, 📁 ARCHIVED; WAITING і ANSWERED — без іконки. Змінюється лише коли сама іконка інша. Немає потрібного емодзі в наборі — іконка не ставиться, пише warn.
- **Переходи статусу:**
  - фотографиня написала питання → WAITING (ESCALATED лишається ESCALATED);
  - фотографиня написала коротке «дякую/добре/гаразд», один емодзі чи стікер → статус не змінюється;
  - підтримка відповіла → ANSWERED; якщо тема ESCALATED і відповіла не та людина, яку кликали, — лишається ESCALATED;
  - 👍 від підтримки на повідомленні фотографині → ANSWERED (з тим самим правилом для ESCALATED);
  - пост бота по задачі/зйомці/розсилці → WAITING;
  - звільнення → ARCHIVED; нове повідомлення від неї → WAITING.
- **Коротка подяка:** до трьох слів, без «?», кожне слово зі словника (дякую, дякуємо, спасибі, добре, гаразд, ок, окей, зрозуміла, зрозуміло, ясно, навзаєм, супер, чудово, так, угу, ага, велике, вам…) або лише емодзі/«+»/стікер.

### Закріплена картка (англійською)

Перший рядок видно смужкою зверху теми на телефоні:

```
📍 Today 08.10: Lviv · Dragon Park 1 · 10:00–20:00
👤 Бланк Анастасія Ігорівна · @user
📞 +380…
🏠 Main point: Lviv · Dragon Park 2
[🔔 Kuznetsov] [🔔 Hupalova]
```

Без зміни — `📍 Today 08.10: no shift`; архів — `📦 Employment ended · 08.10` (лише поки людина неактивна; повернулась — тема виходить з архіву). Картка редагується (без службових повідомлень): при створенні теми, при першому повідомленні дня і щоденною задачею о 07:00 за Києвом.

Якщо сьогодні зміна не на основній точці, перед першим повідомленням дня бот пише в тему `📍 Today at Lviv · Dragon Park 1 (not the main point)`.

### Фотографиня → тема

Обробник стоїть там, де зараз `handleStaffMessage`: після всіх сценаріїв (задачі, пересчет, посилки, побажання). Що дійшло сюди — йде в тему, крім команд `/…`. Stray «Не розпізнав» для співробітниць прибирається.

1. `ensureThread(userId)` під наявним Redis-локом: створює тему, картку, закріплює. Лок зайнятий іншим процесом — чекає його тему до 15 с.
2. Контекст (пост бота, рядок `CONTEXT`): уточнення по задачі, рядок зйомки, заперечення розсилки, відповідь на фінаудит.
3. `copyMessage` у тему; свайп-відповідь фотографині → `reply_parameters` на пару з цитатою (`quote`), якщо цитата не прийнялася — без неї. Альбом буферизується (~1 с) і йде `copyMessages` одним альбомом.
4. Рядок `IN`, оновлення статусу.
5. Підтвердження: реакція ✍ на її повідомлення завжди; текст «Передали в підтримку — відповідь прийде сюди.» — лише якщо до цього 6 год тиші і це не коротка подяка.
6. Тема видалена вручну → нова тема, рядок `⚠️ Previous topic was deleted — history is in the archive.`, повтор один раз. Інша помилка → фотографині «❌ Не вдалося передати повідомлення в підтримку. Спробуй ще раз за хвилину.»

**Звільнені.** Повідомлення від неактивного профілю теж іде в її тему (5 відмов «Account Inactive» за місяць — шуму не буде). Кнопки кабінету для неї закриті, відповідь — українською.

### Тема → фотографиня

1. Відсіюються: сам бот, службові повідомлення (перейменування, закріп), General та інші теми (LOGISTICS).
2. Анонімний адмін або людина не з ролей підтримки → у тему `⚠️ Not delivered: …` з причиною. Мовчки не губимо.
3. Тема людини → `copyMessage` фотографині (форматування без втрат); свайп-відповідь → `reply_parameters` з цитатою. Відповідь на пост `CONTEXT` → контекст іде цитатою-блоком перед текстом (`<blockquote>`). Альбом → `copyMessages`. `rich_message`/`checklist` — наявним шляхом `sendAdminOutboundMessage`.
4. Рядок `OUT`, статус, `UserTimelineEvent` як раніше.
5. Помилка доставки → у тему `❌ Not delivered: … blocked the bot` або текст помилки Telegram.
6. **Стара тема** (тікет/вихідна/задача) → доставляється так само; раз на день у ній рядок `➡️ This conversation now lives here: <link>`.

### Правки й реакції

- `edited_message` з будь-якого боку → `editMessageText`/`editMessageCaption` пари; «message is not modified» ігнорується; заміна медіа — лише лог.
- `message_reaction`: реакція підтримки на повідомлення фотографині ставиться на її оригінал, і навпаки. Бот може поставити одну реакцію — реакція підтримки замінює ✍. 👍 → ANSWERED.

### Покликати і повернути

- Кнопки в картці `🔔 Kuznetsov` (`ADMIN_IDS[0]`) і `🔔 Hupalova` (`CO_FOUNDER_IDS[0]`); лише ролі підтримки.
- Натиснули: статус ESCALATED, у тему `🔔 Kuznetsov, you're needed here · called by Olena` (згадка `tg://user`) з кнопкою `↩ Back to Support`; у приватні — назва теми, копії до трьох останніх повідомлень фотографині без відповіді, кнопки `Open topic` і `↩ Back to Support`.
- Менеджерка далі пише в темі сама — нічого не забирається.
- `↩ Back to Support` (`SUPPORT_IDS[0]`): у тему `↩ Back to Support · from Kuznetsov` зі згадкою, статус WAITING якщо остання питальна від фотографині без відповіді, інакше ANSWERED.
- Кого кликали, той написав у темі → ANSWERED.

### Адмінка бота

Написати співробітниці з профілю (`handleAdminMessageSend`, пряма відповідь) → `ensureThread`, доставка фотографині, копія в тему з рядком `↗ Sent from the bot by Vitalii`, пара `OUT`. Екран: «Sent. It's in Бланк's topic» + кнопка теми. Кнопки «💬 Відповісти» під повідомленням більше немає.

### Тексти для фотографині

| Де | Текст |
|---|---|
| «Написати в сапорт» | **Напиши сюди — передамо в підтримку.** Можна текстом, фото або кружечком. |
| Уточнення по задачі | ❓ **Уточнення по завданню:** «…» Напиши, що саме незрозуміло, — передамо в підтримку. |
| Перше повідомлення після 6 год | Передали в підтримку — відповідь прийде сюди. |
| Збій | ❌ Не вдалося передати повідомлення в підтримку. Спробуй ще раз за хвилину. |

Зникають: «Твій запит створено», «Твоє повідомлення вже в роботі», «Ми закрили твій запит», «Твій діалог з куратором вже відкритий», «Уточнення по завданню закрито», підказка «Натисни кнопку нижче… в правильний topic», англійське «Account Inactive». Старі кнопки «💬 Відповісти» в історії чату відкривають екран «Напиши сюди».

### Перехід

Щойно прапорець увімкнено, разова задача (Redis-ключ `support:threads:migrated:v1`, по одній людині раз на 3 с — ліміт 20 повідомлень/хв у групі):

1. Для кожної людини з активним тікетом, вихідною або темою задачі — `ensureThread`.
2. У новій темі `⬅️ Previous conversation: <links>`; у кожній старій `➡️ Moved to the permanent topic: <link>` і `closeForumTopic`.
3. Тікет CLOSED, вихідна `isClosed`, задача `supportTopicStatus` CLOSED.

Решті тема створюється з першим повідомленням або першою дією адміна.

## Testing

- Чисті модулі: назва (збіг прізвищ, без точки, кирилиця в місті), коротка подяка, переходи статусу, картка, вибір іконки, `msgToHtml` (expandable blockquote, мова `pre`, `text_mention`).
- Сервіс з фейковим API та репозиторієм: перше повідомлення створює одну тему; контекст перед копією; правило 6 год; цитата в обидва боки і відкат без цитати; видалена тема; доставка в стару тему; покликати/повернути; правки; реакції; альбом.
- Після викату: повторити `bot-support-topics-audit.mjs`, `bot-support-lost-messages.mjs` — «Не розпізнав» від співробітниць = 0, нових тем ≈ нових людей.

## Out of scope

LOGISTICS, кандидатки (HR-контур через вебапп), recovery-чат.
